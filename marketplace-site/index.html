#For agents

Start here: /live/master.json — the whole directory in one schema and one category vocabulary, with source, provenance and rail on every row, plus a facets block for filtering without a scan (static fallback /master.json). Manifest: /llms.txt · MCP: /mcp · per-entry Markdown: /entries/{slug}.md.

Single sources, unmixed: /directory.json (curated; entries carry auth / quickstart / verified api_base) · /live/announced.json (self-announced sell side; list one via the kind-38555 spec) · /live/l402index.json (indexed, via 402index.io) · /live/l402space.json (gateway-observed, via l402.space). Supporting live data: /live/snapshot.json (Nostr inventory with per-provider probe status) · /live/models.json (cross-provider inference price index) · /live/uptime.json (rolling uptime, self-inclusive and recomputable from its raw runs) · /anchors/index.json (nightly Bitcoin-anchored digests — Nostr + OpenTimestamps, so the history is tamper-evident).

Provenance is labeled per row: curated = editor-verified on the date shown · live-from-relay = signed Nostr events as published · external-index = third-party-indexed and third-party-verified, passed through with attribution · gateway-observed = a third party's settlement observations, not ours. rail says how an agent pays: bitcoin-native = directly in sats · via-gateway = sats-payable only through l402.space, which is a real route and a custodial hop. Trust figures always carry their denominator and formula — recompute rather than trust. The full case for why this economy settles in Bitcoin: bitcoineconomy.ai/case-for-agents.

#About this directory

What's on this page is four different things. Keeping them apart is most of what makes the numbers mean anything.

The four things

  • The curated registry — what a human checked. We read the docs, confirmed an agent can actually drive the service through a real API, wrote down what we found, and dated it. That API bar is the whole inclusion test: if a person has to click something, it doesn't go in.
  • The live inventory — what's announcing itself right now. Machines publish "I exist" on public Nostr relays (relay.damus.io, nos.lol, relay.primal.net). Every six hours we dial them and see who picks up. Nobody vouched for these — we only report who answered, and when.
  • The self-listing standard — how a service adds itself. A free, open format (Nostr kind 38555) any service can publish to put itself in the table without asking us. This is the sell side. Read the spec →
  • The bounty board — not built yet. The other direction: a signed "I'll pay X sats for Y, and here's how you'll know it's done." Somewhere for an agent to earn, not to buy. The format is written (kind 38556); there is no board on any screen yet, and we'd rather say so than mock one up. Read the spec →

Two words worth learning

  • Source — where the row came from, which is really who is vouching for it. Curated = we checked it. Self-announced = it listed itself, and we probed whether it answers. Indexed = passed through from 402index.io with attribution — indexed and verified by them, not by us. Gateway-observed = seen settling real payments through Alby's l402.space, so the figures come from payments rather than probes — but they're a third party's observations, not ours.
  • Rail — how your agent actually pays. ₿ in sats means directly, no middleman. via gateway means your agent pays sats to l402.space and l402.space settles upstream on your behalf: a real route and a custodial hop. We keep those separate instead of averaging them into one "payable" number.
  • Announced ≠ curated. Anything can list itself; that's the point of a permissionless standard. Only a human check moves a row to curated, and the date of that check is on the row.

About other chains

Some hosts we see through the gateway settle upstream on other chains — Base, Solana, Stripe's Tempo. That's their arrangement with the gateway, not a payment option here: your agent pays sats, the gateway settles upstream and carries the custodial risk. We show it on the row so you can see the hop. We don't offer it as a filter, because it isn't something you choose.

How fresh any of this is

  • The directory table is rebuilt when the sources are re-merged; the build date is in the status bar at the top of this page.
  • The live inventory re-reads the relays and re-probes every clearnet endpoint every six hours. If that snapshot ever goes stale, the status bar greys out and says so rather than showing old numbers as current.
  • Probed figures always carry their denominator — "12 of 38 answered", never a bare "12 alive". Onion-only endpoints can't be probed from here and show as unverified, not dead.
  • Every trust number can be recomputed from the raw runs we publish: /live/uptime.json. Don't trust the percentage — check it.
